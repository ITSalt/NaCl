## Цель и условие завершения

Подготовить доказательный и исполнимый план модернизации NaCl: выявить устаревшие и тяжеловесные конструкции, предложить приоритетные упрощения и способ их проверки. **Основа сохраняется по решению владельца D-11:** знания хранятся в графе; методология определяет структуру и жизненный цикл знаний; фреймворк NaCl обеспечивает реализацию методологии. Графовая основа — заданная граница программы, а не вопрос выбора для исследования. Размер, способ представления и реализации конкретных механизмов могут улучшаться при сохранении необходимых гарантий.

На каждый кандидат указать текущий механизм и его пользу, проблему, предлагаемое изменение, основание с примерами, риск, зависимости, условия проверки и отката. Отдельно различать подтверждённые факты, гипотезы и UNKNOWN. Исследование и изолированные прототипы не означают, что модернизация уже реализована.

Условие завершения: выпущены и независимо оспорены итоговый аудит, рекомендации, целевая методика NaCl и исполнимый backlog отдельной программы внедрения с этапами, зависимостями, критериями приёмки, миграцией и rollback. По приоритетным кандидатам представлены доступные проверки с их границами; непроведённые измерения и неполное покрытие явно переданы как UNKNOWN, без ложных PASS и заявлений об измеренном ускорении. Исторические статусы и независимые partial verdicts сохраняются; решение о графовой основе и подтверждённый ограниченный пакет WP-19 не превращают непроверенные исходные критерии в выполненные. Внедрение NaCl, релиз и изменение его исходников не являются частью этой программы.

## Порядок работы по модернизации

1. **Свести находки.** На основе карты, профильных отчётов и принятых девяти исторических ситуаций сформировать единый реестр механизмов NaCl с доказанной проблемой либо честной гипотезой. Не повторять завершённые исследования только ради статуса.
2. **Выбрать приоритеты.** Для каждого кандидата описать текущий процесс, полезную гарантию, причину тяжеловесности, предлагаемое упрощение, реального потребителя, совместимость клиентов и потенциальный эффект. Ранжировать по пользе, риску и реализуемости; стоимость без измерения — UNKNOWN.
3. **Проверить конкретные гипотезы.** Сопоставлять текущий механизм NaCl с предлагаемым упрощением на релевантном случае; до любой исполняемой проверки закрепить исходное состояние, независимый oracle, позитивный/негативный сценарий, контроль ресурсов и границы graph. Прототипы не внедрять в NaCl. Результат — проверка механизма, не выбор системы хранения знаний.
4. **Независимо оспорить решения.** Для каждого изменения проверить потенциальную потерю требований, корректность и восстановление графовых данных, traceability, доступы и прежние классы дефектов. Недоказанные условия сохранять как UNKNOWN/DEFER, не блокируя выпуск ограниченного плана.
5. **Передать единый исполнимый план.** Выпустить `reports/final-audit.md`, `reports/recommendations.md`, `reports/target-methodology.md` и `reports/implementation-handoff.md`: приоритеты, зависимости, предложенные WP реализации, критерии приёмки и контрольные сценарии, миграцию, совместимость, обратимый rollout/rollback, риски, измеренные результаты и неизвестные. Файлы — части одного плана, согласованные с этим документом; реализация проводится отдельно.

Начальные кандидаты для проверки по имеющимся материалам: семантическая актуализация BA→SA при сохранённом ID (WP-19 BA-2), происхождение evidence и соответствие проверок требованиям (WP-19 DEV-1/DEV-3), согласованность состояния и восстановление графа (WP-19 CTRL-1/CTRL-3). Это исследовательский shortlist, не готовые решения и не исчерпывающее покрытие; их можно уточнить по evidence.

## Риски

| Риск | Как учитываем |
|---|---|
| Подтвердить исходную гипотезу вместо исследования | KEEP допустим; независимый challenge; контраргумент для каждого удаления |
| Удалить полезный gate | Исторический дефект, negative case и альтернативная гарантия обязательны |
| Принять объём копий за сложность | Карта source→overlay→generated, единица анализа — обязанность |
| Объявить Harness заменой по названию | Проверка конкретной версии, гарантии и probe; неизвестное остаётся неизвестным |
| Измерить только успешные прогоны | Сохранять failed/blocked/timeouts, одинаковый rubric, сравнение качества |
| Не получить реальные трассы или бюджет | Static/replay и live результаты разделены; ограничения входят в итог |
| Сам аудит станет тяжёлым | Один отчёт на WP, без NaCl lifecycle/графа/PR на исследование; мерить накладные расходы координатора |
| Scope creep в реализацию | D-2, delivery hold, исходники read-only, отдельная программа внедрения |
