## 0. Подготовка worktree

Работа проводится по зафиксированному снимку. Сначала прочитать применимые AGENTS.md и CLAUDE.md и `spec/research-protocol.md`. Проверить HEAD и git status. Для read-only scout отдельный worktree не нужен; исполняемые probes — в family-cinema по D-3, с отдельными code worktree, выходами и контролем состояния графа. Не запускать стандартный code-dispatch/prepare для этого пакета: шаблон предполагает реализацию и PR, а D-2 требует исследование.

## 1. Факты

Основание: `reports/planning-evidence.md`. Это предварительная разведка. Конкретные утверждения подтвердить по исходникам с SHA и file:line; готового вывода об избыточности нет. Область: bench/; tests/fixtures/; docs/retrospectives/; доступные согласованные трассы проектов.

## 2. Объём

Выбрать приоритетные кандидаты упрощения NaCl на основе evidence и исторических случаев WP-19. Для каждого зафиксировать проблему, текущую обязанность, сохраняемые гарантии графовой модели и методологии, гипотезу, risk и индивидуальные positive/negative controls. При уместности сравнить текущий механизм NaCl с изолированным прототипом предложенного упрощения в одинаковых условиях; прототип не внедряется в NaCl. Измерять стоимость и качество там, где это воспроизводимо и бюджетно допустимо; статические результаты и UNKNOWN сохранять отдельно. Никакой выбор между NaCl и Markdown+Harness не является целью или обязательным вариантом. Сверить стыковые выводы WP-11–14 с принятым WP-19.

### Не входит

Изменение NaCl, внедрение рекомендаций во фреймворк, чужая инфраструктура, внешняя публикация и полномасштабные запуски без ресурсного плана. Результат — исследование, а не diff скиллов.

## 3. Критерии приёмки

1. Для выбранных кандидатов — текущий механизм, графовые/методические инварианты, исторический случай, альтернативный механизм, positive/negative controls, наблюдения и сырые метрики при наличии; ограничения, UNKNOWN и реальные кейсы отдельно от replay.
2. Все подобласти покрыты либо явно исключены с причиной; выводы привязаны к проверяемым источникам.
3. По механизму описаны задача, потребитель, цена, предотвращаемый дефект, простая альтернатива и риск её применения.
4. Отделены факты, измерения, выводы и гипотезы; отсутствующее evidence не заменено уверенностью.
5. Для каждого кандидата дана категория KEEP / SIMPLIFY / MERGE / DELETE / HARNESS / DEFER с условиями применимости; отсутствие кандидатов допустимо при обосновании.
6. Выполнены проверки артефакта из протокола. Исходники NaCl не изменены; экспериментальные изменения family-cinema перечислены, исходное состояние графа восстановлено/сверено. Приложены ограничения и вопросы для следующей программы.

## 4. Порядок сдачи

Исследователь возвращает структурированный отчёт и ссылки на evidence координатору. Координатор проверяет выводы и сохраняет `reports/WP-FRAMEWORK-16.md`; подтверждает критерии до смены статуса. Допустимы REVISE и ACCEPTED; DONE означает принятие исследования, без фиктивных стадий MERGED/PROD. Rollback: отозвать неподтверждённый вывод отдельной записью, сохранить историю, пересдать отчёт; исходники NaCl не меняются; для family-cinema восстановить экспериментальный baseline согласно spec/family-cinema-testbed.md.
