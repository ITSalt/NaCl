## 0. Подготовка worktree

Работа проводится по зафиксированному снимку. Сначала прочитать применимые AGENTS.md и CLAUDE.md и `spec/research-protocol.md`. Проверить HEAD и git status. Для read-only scout отдельный worktree не нужен; любые исполняемые probes — только в disposable sandbox с отдельными выходами. Не запускать стандартный code-dispatch/prepare для этого пакета: шаблон предполагает реализацию и PR, а D-2 требует исследование.

## 1. Факты

Основание: `reports/planning-evidence.md`. Это предварительная разведка. Конкретные утверждения подтвердить по исходникам с SHA и file:line; готового вывода об избыточности нет. Область: nacl-tl-dev*/; nacl-tl-stubs/; nacl-tl-fix/; nacl-tl-hotfix/; nacl-tl-reopened/.

## 2. Объём

BE/FE split, contracts/stubs, spec-first, fix/hotfix/reopen. Малый фикс против большой фичи. Цена возвратов к спецификации; контрактная совместимость; ожидание provider fixtures.

### Не входит

Изменение NaCl, реализации рекомендаций, live-инфраструктура, внешняя публикация и полномасштабные запуски без ресурсного плана. Результат — исследование, а не diff скиллов.

## 3. Критерии приёмки

1. Разбор dev-loop по классам задач; минимальный достаточный контекст; сохраняемые защиты.
2. Все подобласти покрыты либо явно исключены с причиной; выводы привязаны к проверяемым источникам.
3. По механизму описаны задача, потребитель, цена, предотвращаемый дефект, простая альтернатива и риск её применения.
4. Отделены факты, измерения, выводы и гипотезы; отсутствующее evidence не заменено уверенностью.
5. Для каждого кандидата дана категория KEEP / SIMPLIFY / MERGE / DELETE / HARNESS / DEFER с условиями применимости; отсутствие кандидатов допустимо при обосновании.
6. Выполнены проверки артефакта из протокола. Исходники не изменены. Приложены ограничения и вопросы для следующей программы.

## 4. Порядок сдачи

Исследователь возвращает структурированный отчёт и ссылки на evidence координатору. Координатор проверяет выводы и сохраняет `reports/WP-FRAMEWORK-05.md`; подтверждает критерии до смены статуса. Допустимы REVISE и ACCEPTED; DONE означает принятие исследования, без фиктивных стадий MERGED/PROD. Rollback: отозвать неподтверждённый вывод отдельной записью, сохранить историю, пересдать отчёт; исходники не откатываются, поскольку не меняются.
