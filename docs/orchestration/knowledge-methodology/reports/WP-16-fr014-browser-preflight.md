# FR-014: browser preflight исторического экрана

2026-11-02. Временная копия frontend из `8d449ab652568d6f1cd69d9c2b9bdae829a6bb79`; установленная локально Playwright 1.59.1, headless Chromium, viewport 800×600, Node 24.13.1. Next dev server запущен только на loopback с динамическим портом 63484 и после пробы остановлен.

В новом browser context до загрузки установлен синтетический `fc_session_store` с session-test. Browser routes подменяли GET session, GET photos (две синтетические фотографии) и status для p2; fixture SVG возвращался локально. Неизвестные `/api/` и незнакомые origin блокировались, но в v1 маршрутизатор сначала сопоставлял путь: чужой origin с известным `/api/` или `/fixture/` мог получить локальную подмену без записи в unexpected. Непосредственная сетевая отправка в этих ветках не выполнялась; прежнее утверждение о полной регистрации чужих origin было неточным. Вывод: HTTP 200, pathname `/memories/upload`, heading `Загрузите фотографии`, 2 изображения; наблюдались вызовы session/photos/status, неожиданных browser requests или page errors не было.

Это проверка, что один синтетический сценарий экрана отображается; не независимая browser приёмка lightbox, не проверка touch/scroll и не доказательство, что серверная часть не делала исходящих запросов. Ранний повтор preflight выполнен из временного v1, сохранённого как `browser-preflight-v1.saved` (SHA-256 `3d4391034901674424fb926b4e5016e9c99e6e963ef606b04766f2cdd903a347`), с loopback port 63620; exit 0, те же heading/two images и неожиданных browser requests 0. Сервер остановлен. Файл находится во временном каталоге окружения и не является долговременным защищённым хранилищем; raw execution log формального эксперимента ещё не сохранён. После независимого review проверка origin перенесена до пути, serviceWorkers заблокированы; финальный временный runner SHA-256 `c9ed3ed1c3e7bacd3f12dccbb204b1867ad955720644020c884b4cb8a6fccbaa`. Повторный запуск с loopback 63823: exit 0, тот же preflight; пять negative URLs (чужие /fixture и известный /api, неправильный localhost port, IPv6 и localhost hostname) заблокированы и записаны. Две промежуточные версии ошибочно завершались exit 1 из-за изменяемого массива журнала и итоговой проверки; они исправлены до этого запуска. Наблюдение ограничено 2.5 s; WebSocket и server-side network не проверены, OS network sandbox не применялся. Отдельный локальный negative probe на двух временных loopback HTTP servers и Playwright 1.59.1 показал: initial URL разрешён, ответ 302 перенаправляет на другой loopback port, route handler видел только исходный URL, destination server получил 1 запрос, blocked=0. Оба сервера закрыты. Следовательно `context.route` не обеспечивает egress isolation на redirect hops; никакие внешние адреса в этом probe не вызывались. До pilot нужна проверенная OS-level изоляция browser и server, а не только этот routing guard. Временный runner не является долговечным защищённым acceptance harness. До A/B нужны одинаковые данные/входы, проверенный запрет реальной сети обоих процессов и изоляция harness от реализаций. Graph baseline по-прежнему NOT_VERIFIED.
