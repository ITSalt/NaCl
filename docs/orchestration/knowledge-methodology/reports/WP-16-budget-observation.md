# WP-16: наблюдение доступности учёта согласованного бюджета

D-4: суммарный предел одной пары, независимого review и подготовки — до 1.2M input, 120k output и 195 минут; не лимит генерации фото/видео. Исходное разбиение на 500k+500k+200k input и 50k+50k+20k output не оставляло резерва на координацию/подготовку, поэтому не является остатком.

2026-11-02: официальная [документация Codex App Server](https://learn.chatgpt.com/docs/app-server#turn-events) описывает `thread/tokenUsage/updated` для активного thread. Локальная схема `codex app-server generate-json-schema` 0.166.0 также содержит `account/usage/read` с `threadId` и обозначает threadUsage как estimated, когда доступен billing route. Read-only вызов к текущему живому thread через подключённый локальный App Server вернул `threadUsage: null`; `thread/read` поля usage не вернул. Эти наблюдения не говорят, что расход равен нулю, и не дают раздельный общий итог текущего координатора и всех исследовательских субагентов. Сырой account-wide usage и приватные данные не выводились.

2026-11-02 `thread/read` сообщил configured model `gpt-6.1-terra`, provider `openai`; это не доказывает модель каждого ответа или route оплаты. По [официальной таблице Codex](https://learn.chatgpt.com/docs/pricing#token-rates) Standard credit rate для GPT-6.1 Terra: 25 credits/1M input, 1.25 cached input, 125 output. Если вся одобренная квота 1.2M input и 120k output тарифицировалась бы как uncached Standard purchased credits на этой модели, арифметическая верхняя оценка — 45 credits (30+15), без двойного учёта cached input. Это условный расчёт, не фактический остаток, не долларовая цена и не гарантия тарифа/route/tier; Fast и иные модели меняют ставку, подписочный учёт может отличаться.

Временной ориентир: git commit записи D-4 `eaf642b` имеет `2026-11-02 15:32:15 +0300`; подготовка после него включает агентную работу, npm setup и контрольные пробы. Выполнение A/B arms не начиналось; это не означает нулевых затрат на подготовку или review. Установить фактический общий расход и remaining budget по надёжным runtime events/доступным учётным данным, включая cache без двойного счёта. Наличие CLI `/status` или account `/usage` само по себе не доказывает атомарного hard-stop общего multi-thread бюджета. Пока неизмеренный остаток и enforcement не разрешены, пилот не запускать; продолжать разрешённое общее source-only исследование без утверждения, что agent work бесплатна.

Дополнение 2026-11-02: локальные JSONL metadata содержат timestamped `token_count` и отдельные per-call usage записи, а также часть parent/agent lineage; это новые данные по сравнению с `threadUsage:null`. Они позволяют частичную реконструкцию по выбранным sessions, но точная граница подготовки D-4, полный набор относящихся сессий, агрегирование координатора/детей и семантика учёта ещё не установлены. Cumulative snapshots нельзя складывать между собой; cached input включён в input, reasoning output — в output. Между снимками parent thread 12:32:18.219Z и 15:08:47.980Z прирост локального счётчика составляет 367 676 130 input (включая 366 475 520 cached) и 330 738 output; child sessions в этот расчёт не добавлены. Если все эти вызовы отнести к подготовке D-4 и сопоставить output этого счётчика с лимитом, один parent превысил бы 120 000 output. При неизвестной атрибуции и семантике счётчиков это не устанавливает ни исчерпание, ни остаток D-4 и не подтверждает billing. По проверенным настройкам и инструментам подтверждённого общего hard cap для координатора и всех субагентов не найдено; его наличие вне обследованного окружения не исключено. Текст переписки и секреты при проверке metadata не извлекались.
