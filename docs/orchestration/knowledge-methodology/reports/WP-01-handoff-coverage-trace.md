Named query graph-infra/queries/handoff-queries.cypher:52–89, повторённый в nacl-ba-handoff/SKILL.md:408–445 и аналогичных фрагментах nacl-ba-validate/SKILL.md:508–518,551–560,580–589,627–636, считает denominator по BA nodes, numerator по match rows без DISTINCT. При наличии строк последующих entity/role/rule категорий: для двух BA steps, из которых один имеет два target UC, из текста получается 2/2=100%, хотя покрыт один из двух; один source с двумя targets теоретически даёт 200%; иначе общий grouped query может не вернуть строку. Это аналитическое следствие, не исполненный probe. Entities отфильтрованы по type=Бизнес-объект, steps — по русскому Автоматизируется, roles/rules шире; integer rounding тоже влияет на интерпретацию порога.

SA-side nacl-sa-validate/SKILL.md:2277–2292,2340–2351,2397–2408 считает source nodes и EXISTS, не размножая numerator по edge; при нулевом total описывает N/A. Его steps denominator включает русский/английский stereotype либо существующий edge, entities охватывает все BusinessEntity. В rules :2452–2464 independent суммы implemented и out_of_scope могут пересечься: один одновременно mapped и out_of_scope rule логически даёт 200% и gap=-1. Это гипотеза для отдельного negative, не наблюдённый outcome; другие SA summaries используют другие правила. BA и SA показатели нельзя считать одной формулой.

BA named query использует CASE ELSE 0, но некоторые последующие MATCH/grouping при пустых категориях могут не вернуть строку: точный результат надо проверить на изолированной fixture, не заявлять 0 или N/A по памяти. Codex BA validation skills-for-codex/nacl-ba-validate/SKILL.md:19–27 при непустом BA и отсутствующем SA помечает cross NOT_RUN или общий результат PARTIALLY_VERIFIED после internal; отсутствие BA рассматривается отдельно как BLOCKED.
