# WP-01: Docmost diff и частичные результаты

Дополнение к rebuild: `docmost-sync/src/modes/rebuild-manifest.ts:17–49,65–72` сопоставляет remote страницы по нормализованному title и сохраняет локальный contentHash; при коллизии поздний Map entry заменяет ранний без проверки parent/body. Следующий `core/differ.ts:18–30` при прежних local bytes может дать SKIP без remote-body comparison; после изменения local файла используется сохранённый pageId для update (`modes/apply.ts:34–52`, `core/publisher.ts:58–70`). Это условная цепь, не наблюдавшаяся коллизия или реальная запись. Proposed controls: fake remote с одинаковыми title и различными parent/body, rebuild → unchanged apply → changed apply; positive — подтверждённые identity и remote content. Внешний API не запускался.

Pinned NaCl 20fe4c6. Source-only; никаких API-вызовов, sync или тестов. Условные пути кода не означают наблюдённого инцидента.

- `docmost-sync/src/core/scanner.ts:13–45,62–79`, `core/manifest.ts:10–16`, `core/differ.ts:18–45`: diff сопоставляет local files с последним локальным manifest, не с текущим remote body. Отсутствие записи в scan даёт warning `deleted_locally`; это может означать физическое удаление, пустой пропущенный файл или ошибку чтения каталога, которая возвращает пустой список и влияет на diff.
- `modes/apply.ts:34–52,57–79` передаёт publisher creates/updates, сообщает deleted=0 и не вызывает remote delete в этом пути. Warning-only delete — описанная семантика, не автоматически дефект; методы клиента `lib/docmost-client.ts:248–265` существуют, другие routes не исключены.
- `core/publisher.ts:23–52,58–76` повторяет отдельный failed create/update один раз и продолжает; `modes/apply.ts:57–81` вычисляет success как отсутствие ошибок **или** наличие хотя бы одного created/updated. Поэтому при одном успехе и одной окончательной ошибке условно возможны success:true и errors>0, а `index.ts:196–198` завершает exit 0. Consumer подробных ошибок может увидеть partial; фактическое выполнение и upstream parser UNKNOWN.
- При ошибке записи manifest внешний catch `index.ts:201–217` возвращает failure, но уже выполненные remote действия не откатываются указанными строками. `core/manifest.ts:34–40` перезаписывает созданной записи contentHash пустой строкой; при ожидаемой форме pageId следующий diff того же непустого файла может дать update (`differ.ts:25–27`). Реальный response shape и маршрут остаются UNKNOWN.
- `lib/docmost-client.ts:134–176` после create возвращает getPage как any, тогда как publisher :28–33 использует значение как pageId; если API вернёт объект, возможен mismatch, но response не наблюдался. Повтор create после неоднозначного сбоя может создать duplicate, idempotency для этого пути не доказана. `lib/docmost-updater.ts:90–115` описывает локальное Yjs обновление и фоновую persistence, не подтверждая durable remote read-back.
- `modes/rebuild-manifest.ts:26–49,65–94` сопоставляет title с local hash и сообщает success при unmatched; это не доказывает равенство remote body или отсутствие title collisions.

Proposed controls DEFER: mixed success/failure и exit/details, ошибка после remote import, второй diff после create, недоступный каталог, local deletion, одинаковые titles и изменение remote body; positive — content/IDs и manifest read-back для полного scope. Ни один control не выполнен. Связь publisher→CLI и реальная remote semantics не доказаны.
