# WP-01: BA glossary → SA — source-level границы

Pinned NaCl 20fe4c6; независимо сверены root sources. Graph/Cypher, workflows и A/B не запускались; фактическая потеря, runtime, частота и цена UNKNOWN, DEFER.

Root `nacl-ba-glossary/SKILL.md:25–27,33–39,72–80,297–304,318–326` при наличии GlossaryTerm предупреждает и требует confirmation перед full, затем удаляет все `GlossaryTerm` через DETACH DELETE без project filter и создаёт узлы с `id,term,definition,source_id`. Если существовали SA-owned `sa_term` или дополнительные incident edges, они удаляются; показанный recreate не описывает их восстановление. Incremental :393–395,453–460,470–478 сохраняет существующие узлы и SA-поля. Это условный риск при подтверждённом full, не наблюдавшаяся потеря; внешние writers/backup возможны.

Root :339–359 создаёт term из WorkflowStep/BusinessRule без DEFINES; :385–389 требует у каждого term DEFINES или исходящий ALIAS_OF. Уникальный подтверждённый canonical term только из такого источника и без дополнительной связи не удовлетворяет этому пункту проверки; при слиянии с другим источником или внешнем edge условия иные. Статус при данном несоответствии в показанном фрагменте не установлен. Отдельно root glossary :284–289,363–367 разрешает alias с ALIAS_OF без DEFINES, но root `nacl-ba-validate/SKILL.md:414–422` классифицирует каждый term без DEFINES как INFO, не исключая aliases. Это различие source-контрактов, не доказательство блокировки или runtime-сбоя.

Root `nacl-sa-finalize/SKILL.md:225–232` ищет прямой `GlossaryTerm-[:REFERS_TO]->DomainEntity`, тогда как root glossary создаёт DEFINES к BusinessEntity, а SA domain :407–412 — BusinessEntity→REALIZED_AS→DomainEntity. На fixture только с последними связями OPTIONAL MATCH вернёт null SA-поля даже при наличии двухшагового пути; отдельный REFERS_TO writer или ручное сопоставление не исключены. BA validator `nacl-ba-validate/SKILL.md:645–668` описывает другой путь через DEFINES/REALIZED_AS.

Incremental :127–145 описывает сравнение имени для WorkflowStep/BusinessRule; показанный Cypher для WorkflowStep исключает совпадающий term без проверки source_id, поэтому одинаковое имя может скрыть нового кандидата. Аналогичный полный запрос BusinessRule в этом фрагменте не приведён; разные смыслы и последствия в реальных данных не установлены. Альтернатива — versioned ID-stable reconcile с сохранением SA fields, подтверждённым retire и read-back; риски неверного объединения разных понятий, stale aliases и изменения consumer semantics. Предлагаемые controls: SA field/edge при confirmed full, standalone step term, одинаковые имена с разным смыслом и отдельно прямой REFERS_TO; ничего не выполнялось. Независимая сверка проекций: legacy `skills-for-codex/nacl-ba-glossary/SKILL.md`, full-package workflow и installed NaCl 0.2.2 BA leaf совпадают побайтно; SA finalize в этих трёх проекциях также совпадает побайтно. Codex BA leaf :20–30,34–52,63–67,84–104 требует confirmation для destructive full и read-back, но не задаёт root DETACH DELETE, root default full или восстановление SA-owned полей/edges. Codex SA finalize :23–29,42–48 требует glossary extract, но не воспроизводит показанный root REFERS_TO query. Поэтому описанные root outcomes нельзя автоматически приписывать Codex/installed runtime.
