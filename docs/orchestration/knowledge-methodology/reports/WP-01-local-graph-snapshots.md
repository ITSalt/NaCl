# WP-01: локальные кандидаты исторического graph baseline

Исследователь нашёл три пары encrypted snapshot/manifest в family-cinema/graph-infra/handover; README подтверждает, что это handover Neo4j snapshots. Манифесты заявляют даты 19 апреля, 14 мая и 26 сентября 2026 и размеры графов 1006/1014, 1808/2398 и 4365/9273 узлов/рёбер соответственно. Это утверждения манифестов, не независимая проверка содержимого. Самые ранние архивы уже после FR-014 code baseline 8d449ab от 2 апреля. В том Git tree архивов по путям graph-infra/handover и graph-infra/backups нет; это не исключает другие хранилища.

Для апрельской отметки Git commit 41db4574b7bc4250b90ee9e43a765d1178282310 разрешился, и git merge-base --is-ancestor 8d449ab 41db457 вернул 0. Это история кода, не доказательство состояния графа на baseline или отсутствия утечки будущего решения. Упомянутые майский da0b0d5 и сентябрьский 405a688 локально не разрешились, их предковость не установлена. Локальный hash последнего ciphertext 074eaa621ded9ea6d2c90eaebac73731f0c20b0df1724fe892f138e62ac7d5ab идентифицирует файл, но не доказывает аутентичность и связь с manifest.

Дополнительная read-only проверка Git history: каждая из трёх пар ciphertext/manifest впервые добавлена совместно и затронута одним commit в текущей истории (5e1ed04, 80a02f9, 11e2bd9). У манифестов нет отдельного digest ciphertext; `git_sha` относится к коду. Совместное версионирование двух blobs не устанавливает содержимое, авторство, исходное время snapshot, ключ или восстановимость. Family Cinema HEAD 4f3ecb8, tracked status чист; ignored файлы status не охватывает.

Отдельный локальный ignored plaintext backup и journal graph-infra/upgrade-215-journal.md описывают исторический restore в изолированном контейнере; данные файла не читались и не переносились. Старая запись не доказывает текущее восстановление или равенство baseline. Reconciliation JSON и board snapshot — не полные backup графа.

Следующие шаги: найти независимый export до code baseline с доказуемым provenance; проверить соответствие требованиям, semantic fingerprint и отсутствие solution leakage; при доступности ключа проверить restore только в отдельной временной сетево изолированной БД и сравнить состояния. Не выводить содержимое или ключи и не импортировать в общий граф. Синтетический baseline возможен только с явной маркировкой и отдельной проверкой применимости; это не исторический snapshot. Ключи, содержимое backup, live graph и сеть при данной сверке не использовались.
