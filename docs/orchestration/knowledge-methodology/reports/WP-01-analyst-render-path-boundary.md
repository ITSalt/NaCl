# WP-01: Analyst Tool graph → Markdown и граница пути

Pinned NaCl 20fe4c6; две независимые проверки исходников. Production/реальный сервер и graph, существующий проект и A/B не запускались; ниже описаны контролируемые Fastify inject probes с synthetic driver. Состояние реального graph, доступность API и права процесса UNKNOWN. Категория DEFER.

В `analyst-tool/server/src/render/markdown/{entity,uc,form}.ts` свойство `source_file` читается из соответствующего Neo4j node (entity :46–57, UC :64, Form :56). После проверки на отсутствие (entity :284–291, UC :400–407, Form :246–253) renderer вычисляет `path.resolve(projectRoot, source_file)`. Dispatcher `render/markdown/index.ts:41–75` передаёт результат, а зарегистрированный `/api/v1/render/markdown` (`server/src/index.ts:123–136`, `routes/render.ts:41–61`) выполняет mkdir и writeFile; в показанной цепочке проверки, что путь остался внутри projectRoot, нет.

Условный graph node с `../outside.md` или absolute source_file может разрешиться вне root, а существующий symlink внутри root — указать наружу; при достаточных правах процесса запись может создать или перезаписать файл. POST выбирает subtype/relatedId, а не задаёт source_file напрямую: влияние зависит от фактических graph properties, доступа к API и прав процесса. Config `server/src/config.ts:59–90` выбирает repoRoot из настроек/окружения/cwd и по умолчанию использует localhost; реальная конфигурация/exposure не проверялась. Ветка `services/skill-runner.ts:207–240` тоже пишет результат, но её доступность через HTTP в проверенном scope не установлена.

`analyst-tool/server/src/render/markdown/markdown.test.ts:334–336,514–516,657–659` проверяет обычные resolve cases; проверка traversal board name в `analyst-tool/server/src/services/skill-runner.test.ts:143–147` относится к другой ветви и не доказывает защиту graph source_file. Наличие этих tests не означает их выполнение здесь; иные guards вне исследованной цепочки не исключены.

## Атомарная карточка 07.5-AT-ENTITY-PATH

Область graph → локальная Markdown-проекция, отдельный Analyst Tool route, не Docmost: pinned NaCl 20fe4c6, `analyst-tool/server/src/render/markdown/entity.ts:46–57,270–291`, `render/markdown/index.ts:41–55`, `routes/render.ts:26–33,41–74`. Вход — entity subtype/id и graph record; выход — файл и HTTP response. Путь берётся из source_file, project root — из конфигурации; конкретный пользователь route и deployment config UNKNOWN. Потребитель — локальный файл и HTTP client; graph record — источник данных рассматриваемой проекции.

При вызове entity-render путь source_file обязателен для показанной ветви: его отсутствие отклоняется 409, предотвращая запись без указанного назначения, но не проверяя его границу. На успешной ветви показаны один recursive mkdir, один writeFile и ответ; entity renderer параллельно вызывает fetchEntityData и fetchEnums (`entity.ts:270–273`), что не устанавливает число сетевых операций. Число graph reads в других ветвях, реальная частота, подтверждения вне route, цена, latency и историческое основание UNKNOWN. Находка не устанавливает возможность атакующего задать graph property или вызвать endpoint. Два disposable synthetic runs и их ограничения описаны ниже; они показали записи synthetic sentinel вне test project, но внутри temp sandbox, без реального graph/API/deployment.

Предлагаемый для исследования путь — ограничение destination project root с контролем symlink, overwrite и read-back; он может запретить намеренные внешние пути и изменить семантику overwrite, а одна предварительная realpath проверка не исключает TOCTOU. DEFER; высокая уверенность только для описанного synthetic fixture. Повторение тех же условий с отказом traversal/absolute/symlink и неизменённым sentinel поставило бы под сомнение воспроизводимость соответствующей находки. Проверка альтернативы должна отдельно включать допустимый внутренний путь, заранее существующий файл и подмену symlink во время операции; альтернатива и гонка не проверены.

## Происхождение source_file

Две source-only проверки `nacl-migrate-sa/scripts/{parse_sa.py,generate_sa_cypher.py,validate_sa_ir.py}` и adapters показывают: обычные adapters формируют source_file из пути прочитанного документа; при невозможности `resolved_path.relative_to(project)` они возвращают исходный путь, а не отказывают (`inline_table_v1_sa.py:140–142,199–211`, `frontmatter_v1_sa.py:134–135,225–237`). Чтение документа происходит до такого преобразования, поэтому symlink наружу — условный исследовательский сценарий, не обнаруженный факт в данных пользователя.

Генератор :20–31,51–66,101–189 переносит `source_file` из SaIR в Cypher без собственной проверки confinement; SV8 `validate_sa_ir.py:245–259` проверяет заполненность для верхних коллекций, не существование/границы/symlink. При обходе validation отсутствующее поле по default становится пустой строкой и может заменить прежнее значение через ON MATCH. Это вывод по исходнику, не выполненная миграция и не доказательство возможности недоверенного пользователя подменить SaIR или вызвать endpoint.

Попытка отдельно проверить чтение внешнего файла SA adapter через synthetic symlink была остановлена **до запуска adapter**: более строгий sandbox с read allowlist завершил canary процесс кодом -6 без диагностического вывода. Проверку не продолжали и ограничения не ослабляли; временные каталоги удалены. Поэтому утверждение о чтении по symlink остаётся source-level гипотезой, не воспроизведённым результатом.

## Disposable воспроизведение

Координатор и независимый исследователь отдельно создали одноразовые копии `analyst-tool` из `git archive 20fe4c6`, скопировали уже имевшиеся локальные dependencies без npm install и проверили отсутствие symlinks, выходящих из temp. Node v24.13.1; локальные версии источника dependencies: fastify 4.29.1, tsx 4.21.0, neo4j-driver 5.27.0; соответствие установленного дерева pinned lockfile не проверялось. HOME/NACL_HOME/TMPDIR/project находились в temp. До каждого опыта sandbox-exec с запретом сети и записи вне temp отклонил canary записи в соседний temp-каталог и loopback connect 127.0.0.1:9 с EPERM/EACCES; эти canary подтверждают только конкретные операции.

В копии импортирован реальный `renderRoutes`, graph заменён на fake driver с синтетическим `source_file`, HTTP выполнялся только через Fastify `inject`, без listen/socket. Координатор проверил entity, независимый исследователь — entity/uc/form: для каждого normal, `../`, absolute и symlink пути получили HTTP 200 и перезапись заранее созданного синтетического sentinel. Normal target был внутри temp project; остальные targets — вне project, но **внутри общего разрешённого temp sandbox**. В symlink case изменён его target. Оба temp дерева удалены.

Это независимое воспроизведение поведения скопированного handler при конкретных synthetic records и локальных зависимостях, а не обращение к реальному Neo4j, существующему проекту или внешнему API. Оно не устанавливает, кто может изменять `source_file` или вызывать endpoint в конкретном deployment, и не подтверждает реальную эксплуатацию/потерю данных.

Альтернатива для будущего исследования — scope-aware разрешение путей с проверкой symlinks/realpath, preview/подтверждённым overwrite и read-back. Риски альтернативы: запрет легитимных внешних файлов, TOCTOU при одном prefix-check и изменение существующих контрактов. Перечисленные traversal, absolute, symlink и normal controls выполнены только в disposable synthetic fixture выше; поведение альтернативы и пользовательский deployment не проверялись.
