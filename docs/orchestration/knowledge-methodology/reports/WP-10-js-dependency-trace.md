## Атомарная карточка 10.2: JS closure diagnose

- **Область и источник:** Skills-only упаковка, pinned NaCl 20fe4c6; `scripts/build-codex-skills-only.mjs:240–282`, `scripts/check-skills-only-bundle.mjs:76–90`, `codex-plugin-src/package/skills/nacl-diagnose/SKILL.md:8–13`.
- **Цель, вход и выход:** самодостаточное дерево отдельного skill; вход builder — полный package, выход — per-skill resources. Вызывающий — packager; потребитель рассматриваемого ресурса — diagnose runner. Источник истины для конкретного probe — сгенерированная временная копия и зафиксированные результаты ниже; для контракта — pinned source.
- **Обязательность и частота:** указан локальный runner; частота фактических вызовов UNKNOWN. Число реальных чтений, записей, передач и подтверждений UNKNOWN; статический scanner/checker не даёт измерения runtime.
- **Предотвращаемый дефект:** недоступная локальная зависимость при загрузке runner; текущий checker проверяет другой ограниченный класс ссылок. Историческая причина и измеренная цена UNKNOWN.
- **Наблюдение:** fresh disposable сборка вернула VERIFIED checker, но runner — MODULE_NOT_FOUND; изменённый временный контроль с vendor дошёл до NOT_RUN/PROJECT_MCP_NOT_CONFIGURED. Независимое повторение и границы приведены ниже. Активный installed route и поведение вне fixture UNKNOWN.
- **Альтернатива и гарантия:** исследовать явный dependency manifest и per-skill load check; они должны учитывать dynamic/conditional require и различия Node/platform, иначе можно потерять полноту closure или portability. Эффективность не измерена.
- **Категория/confidence/falsifier:** DEFER; высокая уверенность только для описанного воспроизведения, общая полнота UNKNOWN. Negative: fresh bundle без literal require target должен обнаруживаться до выдачи полного VERIFIED; positive: полный изолированный fixture загружается без обращения к соседнему skill. Это proposed controls, не выполненные проверки альтернативы. Воспроизводимая свежая сборка того же SHA, где vendor присутствует и неизменённый runner загружается, либо checker отклоняет именно отсутствующий vendor до VERIFIED, поставила бы под сомнение воспроизводимость соответствующего вывода; наблюдённые пробы она не отменит.

## Положительный контроль загрузки

В отдельной disposable-копии исходный diagnose bootstrap сначала проверен по относительным файлам/директориям и SHA-256; затем **только в этой копии** добавлен vendor directory из установленного nacl-init, с проверкой SHA-256 копии vendor. Это намеренно изменённая фикстура, не разрешённый способ разрешения зависимости в реальном Skills-only bundle и не изменение установленного пакета.

При тех же Node v24.13.1 и sandbox-exec profile (сеть запрещена, запись только во временный каталог), пустых temp HOME/project/TMPDIR и очищенном Node environment копия `--diagnose-only --project-root <temp>` завершилась exit 0 и выдала JSON `status: NOT_RUN`, `code: PROJECT_MCP_NOT_CONFIGURED`, `mutation: NONE`, `network: NONE`, `docker: NOT_INSPECTED`; `MODULE_NOT_FOUND` не было. Vendor CJS загружен в модифицированной копии; это подтверждает, что в данной контрольной среде его добавление устранило наблюдённый ранний loader failure и позволило дойти до ветки диагностики пустого проекта. Это не проверка parsing TOML, фактического проекта/графа/MCP или установленного skill; принудительное срабатывание sandbox network deny отдельно не тестировалось. Временный каталог удалён.
