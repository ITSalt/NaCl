## Узкая проверка разрешения пути

В одноразовую временную директорию отдельно скопированы installed diagnose и init bootstrap trees. Перед каждой пробой сверено относительное множество **файлов** и SHA-256 каждого файла, а также отсутствие symlinks в источнике. При Node `v24.13.1`, с удалёнными `NODE_OPTIONS`/`NODE_PATH`, diagnostic harness вызвал только `createRequire(<copied codex-config-contract.mjs>).resolve('./vendor/smol-toml-1.7.0.cjs')`, не исполняя скопированный модуль или vendor. Diagnose mirror вернул `MODULE_NOT_FOUND` (exit harness 2); независимая init mirror — `RESOLVED_EXPECTED` (exit 0). Временные директории удалены.

Это воспроизведённый **отказ разрешения пути в disposable-копии** и положительный контроль разрешимости, не запуск diagnose workflow или доказательство корректности vendor. Код пробы не содержит сетевых вызовов, но отдельная OS network isolation не устанавливалась; actual route, Node окружение пользователя и MCP не проверялись. Exit 2 принадлежит harness. Отдельные пустые директории не сравнивались.

В новой disposable-копии diagnose bootstrap отдельно сверены относительные пути файлов **и директорий**, SHA-256 файлов и отсутствие symlinks. ## Положительный контроль загрузки

В отдельной disposable-копии исходный diagnose bootstrap сначала проверен по относительным файлам/директориям и SHA-256; затем **только в этой копии** добавлен vendor directory из установленного nacl-init, с проверкой SHA-256 копии vendor. Это намеренно изменённая фикстура, не разрешённый способ разрешения зависимости в реальном Skills-only bundle и не изменение установленного пакета.

При тех же Node v24.13.1 и sandbox-exec profile (сеть запрещена, запись только во временный каталог), пустых temp HOME/project/TMPDIR и очищенном Node environment копия `--diagnose-only --project-root <temp>` завершилась exit 0 и выдала JSON `status: NOT_RUN`, `code: PROJECT_MCP_NOT_CONFIGURED`, `mutation: NONE`, `network: NONE`, `docker: NOT_INSPECTED`; `MODULE_NOT_FOUND` не было. Vendor CJS загружен в модифицированной копии; это подтверждает, что в данной контрольной среде его добавление устранило наблюдённый ранний loader failure и позволило дойти до ветки диагностики пустого проекта. Это не проверка parsing TOML, фактического проекта/графа/MCP или установленного skill; принудительное срабатывание sandbox network deny отдельно не тестировалось. Временный каталог удалён.

Proposed будущие controls: explicit dependency manifest/recursive CommonJS dependency closure, missing vendor и package-local resolution до выполнения runner, положительный контроль без cross-skill доступа. Риски: динамические requires и неверные интерпретаторы; цена/runtime UNKNOWN, DEFER.
