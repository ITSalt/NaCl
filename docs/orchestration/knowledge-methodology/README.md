# Актуализация знаний и упрощение методологии

Программа `knowledge-methodology` по концепции единого оркестратора (pepper-orchestrator).
Создана 2026-11-02. Тег в сообщениях и заголовках PR: `[KNOWLEDGE]`.

## Где что лежит

| Путь | Что |
|------|-----|
| `status.md` | единственный источник состояния: волны, пакеты работ, очередь владельца, журнал |
| `PLAN.md` | цели, объём, волны, гейты, риски |
| `decisions.md` | решения D-n, допущения A-n, вопросы для исследования Q-n (только дописывается) |
| `work-packages/` | один файл на пакет работ, `_TEMPLATE.md` — шаблон новых |
| `bugs/` | один файл на дефект, найденный по ходу |
| `reports/` | отчёты сверок, живых проверок, гейтов (создаётся по мере надобности) |
| `release/` | листы выкатки, runbook, rollback (создаётся по мере надобности) |
| `orchestration/protocol.md` | протокол сессий и сообщений этой программы |
| `orch.yaml` | модули, сессии, окружения, защитные правила |

## Правила в одном абзаце

Пишет сюда только координатор. По D-2 программа исследовательская: исходники NaCl и установленные скиллы остаются без изменений. Исследователи читают области и сдают evidence; координатор проверяет и сохраняет отчёты. D-1 не расширяет этот объём: delivery на hold. Реализация рекомендаций — другая программа.

План: [PLAN.md](PLAN.md). Единый протокол: [spec/research-protocol.md](spec/research-protocol.md). Подготовлены 18 DRAFT-пакетов, исследования ещё не запущены. Следующий шаг — начать с WP-FRAMEWORK-01 и зафиксировать карту/корпус до изучения областей. Состояние всегда сверяется по status.md.
