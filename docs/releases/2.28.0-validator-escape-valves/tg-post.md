NaCl 2.28.0 — validator-escape-valves

Два предупреждения валидатора, которые не могли стать зелёными, получили проверяемый «клапан», а дефект миграции, превращавший описания шагов в номера, исправлен и теперь заметен. Всё найдено при валидации family-cinema, воспроизведено RED на одноразовом Neo4j и закрыто GREEN.

Термины. **L3.8** — проверка обратного покрытия: каждый шаг сценария с актором `System` должен реализовываться хотя бы одним требованием (ребро `REALIZED_BY`). **L13.9** — проверка пересечения кэшей: две политики `CachePolicy` с одинаковым `storage_kind` на одном эндпоинте. **Клапан** — свойство узла, которое исключает его из проверки. Прецедент — `anchor_exempt` для L3.7 из 2.21.0.

Что было.

1. У L3.8 не было выхода. После привязки 383 требований в family-cinema L3.8 показал 202 шага. По оценке владельца около 60 из них — чистый рендер, навигация и клиентская обвязка («отобразить список», «перенаправить», «очистить sessionStorage»), у которых законно нет правила. Вердикт переходит в WARN уже с 5 предупреждений, поэтому PASS был достижим только ценой мусорных требований на каждый рендер.

2. L13.9 срабатывал на намеренное наслоение. DEC-042 в family-cinema сознательно кладёт in-app кэш Cache API поверх runtime-кэша Service Worker: имена кэшей разные, URL версионированные и неизменяемые. У L13 по замыслу «нет исключающих свойств». Для структурных проверок это верно, для эвристики пересечения — нет. Проект уже начал писать самодельное `l13_9_accepted`, которое валидатор не читает.

3. Мигратор писал номера вместо описаний. В легаси-таблицах `| Шаг | Актор | Система | Данные |` адаптер брал колонку «Шаг», в которой лежит номер, поэтому в граф попадали описания `1`, `2`, `7a`. Колонка «Актор» (в этом формате в ней текст действия пользователя, а не роль) превращалась в `actor=User` на каждой строке, а колонка «Система» терялась. Во втором формате `| # | Актор | Действие | Система |` при пустом «Действие» получалось описание `--`. Валидатор ничего из этого не показывал.

Что теперь.

1. `ActivityStep.coverage_exempt` — клапан для L3.8, `CachePolicy.overlap_accepted` — для L13.9. Контракт одинаковый: причина (`*_reason`) обязательна; флаг без причины — отдельная находка (L3.9 и L13.10, WARNING); pre-flight (Step 0d) показывает число исключений, так что долг виден и при зелёном гейте. Для L13.9 флаг должен стоять на **обеих** политиках пары: согласие одной стороны — не согласие. Структурные проверки L13.0–L13.8 по-прежнему без исключений.

2. Что можно исключать: рендер уже полученных данных, навигацию, клиентскую обвязку. Что нельзя никогда: бизнес-правило, валидацию, запись, внешний вызов, безопасность, деньги. `nacl-sa-uc` ставит флаг при авторинге после подтверждения. `nacl-sa-flags suggest-coverage-exempt` предлагает кандидатов на уже заполненном графе. Он только сообщает и ничего не пишет; шаги со словами-маркерами правил («проверяет», «сохраняет», «оплата»…) помечаются как `review`.

3. Мигратор: колонка с номером шага больше никогда не становится описанием. Колонка реакции системы распознаётся, и каждая строка разбирается так: пусто у пользователя → `System` + текст системы; пусто у системы → `User` + текст пользователя; заполнено обе → `User` + `пользователь → система`. Новый L3.6b (INFO) считает по UC описания-номера и заглушки, поэтому такой дефект виден после любой миграции.

4. Попутная находка. Фенс L3.8 содержал аннотацию `-- opt-in`, но `--` в Cypher не комментарий, и Neo4j 5.26 отвечает `Invalid input`. Запрос, скопированный «символ в символ», как требует сам скилл, не выполнялся. L3.8 и L13.9 переведены на `//`. Та же аннотация `-- REQUIRED FILTER` осталась в других проверках (L3.7, L4–L7, L9) — это отдельная задача.

Доказательства. `tests/graph/regression-validator-escape-valves.sh` — 8 кейсов на одноразовом Docker-Neo4j, Cypher извлекается из отгружаемого SKILL.md. На старом тексте скилла 6 кейсов валидатора падают, на новом 8/8 зелёные. Classifier: 17/17 (на старом коде 3 падают). Мигратор: 126/126 (122 + 4 новых; на старом адаптере новые падают с `'1'`, `'7a'`, `'--'`). Node-тесты 533/0 (база 529/0). Живой прогон на графе family-cinema ещё не делался.

Обновление проекта. Самодельное `l13_9_accepted` переименовать в `overlap_accepted` — однострочный Cypher в release notes. Пройтись по `nacl-sa-flags suggest-coverage-exempt` и пометить принятые шаги, каждый со своей причиной. Проектам, мигрированным из двухколоночных таблиц, прочитать L3.6b.
